3. Goals, Scope, and Design Principles

3.1 System Goals

  • Provide an automated, standalone pre-ingestion gate for all technical Markdown documents entering the RAG pipeline.
  • Achieve 100% deterministic rule enforcement with zero false passes on syntactic or structural defects.
  • Provide explainable, actionable diagnostics: every issue must report line number, rule code, severity, impact, and fix.
  • Operate autonomously in continuous background daemon mode or ad-hoc single-file/batch CLI modes.

3.2 Scope and Boundaries

  • In-Scope: Markdown syntax, YAML front matter, heading outline hierarchy, code fence tagging, Mermaid diagram syntax, table formatting, link/image validity, YouTube timestamp arithmetic, security secrets scanning, and file routing.
  • Out-of-Scope: Vector database management (e.g. Milvus/Qdrant), embedding computation, and LLM text generation (semantic review is planned for Phase 3/4).

3.3 Core Design Principles

  • Deterministic over Probabilistic: A table is either structurally valid or invalid. A machine validator must guarantee repeatable, zero-cost, sub-10ms verification without probabilistic hallucinations.
  • Dynamic Template Learning: Rather than hardcoding fields, the verifier introspects RAG-SAMPLE-MASTER-TEMPLATE.md dynamically to learn required metadata, types, and section sequences.
  • Non-Destructive Routing: Input files are never modified in-place or deleted. Defective files are quarantined in failed/ alongside companion diagnostic reports.
  • Air-Gapped Security: Executes completely on-premise without transmitting documents across cloud boundaries, protecting enterprise IP.
