7. Problems Faced and Solutions

Problem-Solution Matrix

The following table details all 8 major engineering obstacles encountered during the project, their verified root causes, engineering fixes, and measured outcomes:

#Problem EncounteredRoot CauseEngineering SolutionVerified Outcome
1 Microsoft 365 SMTP Auth Disabled (535 5.7.139) Radiant Global Tech enterprise tenant policy disabled basic SMTP authentication on smtp.office365.com, returning '535 5.7.139 Authentication unsuccessful, SmtpClientAuthentication disabled for Tenant'. Re-routed notifications through an authorized personal Gmail SMTP relay (mohitrajsingh2601@gmail.com) utilizing Google 16-character App Passwords, delivering directly to mohit.raj@radiantglobaltech.com. Added dual STARTTLS/SSL support in agent.py. 100% reliable email delivery with full Excel workbook attachments without requiring tenant-wide policy alterations.
2 Windows Console UnicodeEncodeError on Emoji (Clip Icon) Windows PowerShell environment running standard legacy code pages (cp1252/cp437) crashed with UnicodeEncodeError when attempting to print the raw paperclip emoji glyph in terminal logs. Replaced raw emoji characters in email HTML templates with standard HTML numeric character entity '📎' and replaced terminal log strings with clean ASCII indicators ([ATTACHMENT], [PASS], [FAIL]). Complete cross-platform stability across all Windows PowerShell, CMD, and Linux shell environments without encoding crashes.
3 Email Body Character Limit & Clutter from Raw Inline Dumps Initial implementations embedded the full issue table directly into the HTML email message body. Documents with 50+ errors caused email bodies to exceed 100 KB, triggering mobile client truncation, character limits, and severe visual clutter. Decoupled executive notification from forensic details. Streamlined the email HTML body into an executive status card (total files, pass/fail counts, timestamps, attachment callout) and routed all line-by-line issue details exclusively into the attached Excel spreadsheet. Clean, lightweight executive email body (<5 KB) with complete diagnostic forensics accessible in the structured Excel attachment.
4 Multi-Document Failure Congestion in Single-Sheet Spreadsheets Early Excel report implementation dumped all issues from all batch files into a single flat worksheet ('Issue Details'). Reviewers could not easily distinguish which issues belonged to which document or filter errors by file without complex multi-column filtering. Re-engineered generate_excel_report() using openpyxl to create a dynamic multi-tab workbook: a master 'Summary' tab serving as an index, followed by isolated, dedicated worksheet tabs for each individual document named after the file. Reviewers can navigate directly to specific document tabs with frozen headers, column filters, and wrapped descriptions.
5 Excel 31-Character Worksheet Name Limit & Duplicate Stem Collisions Real-world enterprise document filenames (e.g. RAIN-09-INT-SQLSERVER-AV-0002.md) exceeded Excel's rigid 31-character sheet title limit; multiple files with long shared prefixes produced identical truncated titles, causing openpyxl to crash with 'Sheet title already exists'. Implemented _safe_sheet_title(name, existing_titles) algorithm to sanitize illegal characters (\ / * ? : [ ]), clamp titles safely to 31 characters, and append collision counters (e.g. ' (2)'). 100% crash-free multi-tab Excel generation across arbitrary filename lengths and naming patterns.
6 Raw Machine Timestamps in Reports and UI (20261104_155642) Filesystem timestamp string was passed directly into display columns and email headers. Decoupled stamp_file (strftime('%Y%m%d_%H%M%S')) for filenames from display_time (strftime('%Y-%m-%d %H:%M:%S')) for visible report tables, emails, and spreadsheets. Clean, professional, human-readable ISO-like timestamps across all reports, emails, and spreadsheets.
7 Master Template Schema Evolution & Legacy Context Lines Upstream master template eliminated legacy context lines ('**Doc ID:** ...'), obsolete H1 header lines, and fields like source_url/version, moving sources to the front-matter 'references' list of records. Existing documents still contained old syntax. Extended verifier.py to parse 'records' schema in front matter, added section_types regex mapping to infer section types from H2 titles, added optional_keys: [ekg_config_version], and introduced legacy cleanup rules E066 (context lines), E067 (H1 header lines), and E068 (legacy sections). Golden master template passes with 0 errors; legacy documents are cleanly flagged for modernization without false alarms.
8 Stale Mutation Test Failures Post-Schema Migration test_mutations.py looked for deleted template strings (version: '2.1', old context lines), causing AssertionErrors. Completely overhauled test_mutations.py to test the new schema (references missing name, bad url, bad type, legacy keys/lines, new section headings), updating the test suite to 46 mutations. Achieved '46 mutations, 0 problems' (100% pass rate).
